## Objective

Create Lagune's first virtual machine, **with no public IP address**. Connect to it through Azure Bastion. Set auto-shutdown. Turn on its backup. Write the cost sheet.

## Roles

| Role | What it does |
|---|---|
| **Ops** | Creates the resource group, its tags, the budget alert, the network and the machine. |
| **Security** | Checks the network security group. Stores the password in the team vault. |
| **Dev** | Asks Claude Code for the monthly cost and how to switch the machine off, and checks the answer on the official calculator. |

## Prerequisites

- LAB-01 to LAB-05 done. You hold the Owner or Contributor role on your resource group, or on the training subscription.
- **Prepared by the trainer**:
  - the training region: `<TRAINING_REGION>`;
  - the machine size allowed by the Azure policy: `<ALLOWED_SIZE>`;
  - a budget alert on the subscription, and rules that limit regions and sizes;
  - the team password vault.
- **Check that your region supports Bastion Developer.** Bastion Developer is free, but it handles **one machine at a time** and exists only in **some regions**. Look at the "Regional availability" list on https://learn.microsoft.com/en-us/azure/bastion/bastion-sku-comparison. If the region is not listed, use the **Bastion Basic variant** in step 5 (paid, delete it the same evening).
- A short, unique prefix for your team: `<PREFIX>` (for example `lagune01`).

## Steps

### 1. The resource group and its tags (Ops role)

Cost first: a resource group, the project's "box", with tags.

In the Azure portal (https://portal.azure.com): **Resource groups**, **Create**.

- Name: `rg-<PREFIX>-vm`
- Region: `<TRAINING_REGION>`
- **Tags** tab: add these five tags (these are the same keys as in the Terraform code of LAB-07):

| Name | Value |
|---|---|
| projet | lagune-ops |
| formation | AZM-201 |
| environnement | formation |
| proprietaire | `<TEAM_NAME>` |
| expiration | `<YYYY-MM-DD>` (the last day of the course) |

Other way, from the command line:

```powershell
az group create --name rg-<PREFIX>-vm --location <TRAINING_REGION> --tags projet=lagune-ops formation=AZM-201 environnement=formation proprietaire=<TEAM_NAME> expiration=<YYYY-MM-DD>
```

**Check**:

```powershell
az group show --name rg-<PREFIX>-vm --query "{nom:name, region:location, etiquettes:tags}" --output json
```

The five tags appear.

### 2. The budget alert (Ops role)

Azure portal: **Cost Management + Billing** (or **Cost Management**), **Budgets**, **Add**.

- Scope: your resource group `rg-<PREFIX>-vm`.
- Monthly amount: the one the trainer gives (`<BUDGET_AMOUNT>`).
- Alerts: one at 50%, one at 90%, to the team address.

**Check**: the budget shows in the list, with its two alerts.

Reminder: a budget **warns**, it stops nothing. Alerts arrive with a little delay. It is up to you to switch off.

### 3. The virtual network, subnet and network security group (Ops and Security roles)

In `rg-<PREFIX>-vm`, create:

| Resource | Name | Setting |
|---|---|---|
| Network security group | `nsg-<PREFIX>-serveurs` | No inbound rule added |
| Virtual network | `vnet-<PREFIX>` | Address space `10.10.0.0/16` |
| Subnet in the virtual network | `snet-serveurs` | `10.10.1.0/24`, network security group: `nsg-<PREFIX>-serveurs` |

Same tags on every resource (**Tags** field).

**Check**: open `nsg-<PREFIX>-serveurs`, **Inbound security rules**. Only default rules are there. Ask Claude Code:

```text
Explain each rule of the network security group nsg-<PREFIX>-serveurs, line by line.
Which rule keeps the Internet out? Cite the Microsoft Learn page.
```

You must be able to say why **nothing** comes in from the Internet. A rule nobody can explain is a rule to examine.

### 4. The Windows Server virtual machine (Ops role)

Azure portal: **Virtual machines**, **Create**, **Azure virtual machine**.

- Resource group: `rg-<PREFIX>-vm`. Name: `vm-lagune-01`. Region: `<TRAINING_REGION>`.
- Image: **Windows Server** (the version the portal offers, Datacenter edition).
- Size: `<ALLOWED_SIZE>`, the smallest that is enough. If the portal refuses a size, it is the trainer's policy at work: take an allowed size.
- Local administrator account: a name of the team's own (the portal refuses `admin` and `administrator`). A **long** password, generated by the password manager.
- **Public inbound ports: None.**
- **Networking** tab: network `vnet-<PREFIX>`, subnet `snet-serveurs`, **Public IP: None**. NIC network security group: **None** (the subnet's one is enough).
- Same tags (**Tags** tab).

The **Security** role stores the password in the team vault. It goes neither in the repository, nor in a message, nor in a conversation with Claude.

**Check**:

```powershell
az vm list-ip-addresses --resource-group rg-<PREFIX>-vm --name vm-lagune-01 --output table
```

There is a private address (`10.10.1.x`) and **no public address**.

### 5. Connect through Azure Bastion (Ops role)

**Bastion Developer variant (free, one machine at a time, limited regions).**

1. Azure portal, your machine `vm-lagune-01` (or its virtual network), **Connect**, **Bastion**.
2. Pick the authentication type (user name and password), type the user name and the password from the vault, then **Connect**.
3. Bastion Developer deploys itself into the network. The session opens in a browser tab.

**Bastion Basic variant (paid, if the region is not on the list).** Billing starts as soon as it is deployed: delete it at the end of the session.

1. Virtual network `vnet-<PREFIX>`, **Connect**, **Bastion**, **Configure manually**.
2. Tier: **Basic**. Subnet `AzureBastionSubnet` of size **/26 or larger** (for example `10.10.2.0/26`). A public IP address **for Bastion** (never for the machine).
3. **Review + create**. Allow about ten minutes.
4. Then **Connect**, **Bastion** on the machine.

**Check**: a Windows Server desktop shows in your browser. If the window does not open, allow pop-ups for the portal.

If the connection fails, look at the network security group rules with Claude Code, **never** by opening port 3389 to the Internet.

### 6. A file to protect (Ops role)

In the machine (through Bastion), open PowerShell and create a file:

```powershell
New-Item -Path C:\Lagune -ItemType Directory -Force
Set-Content -Path C:\Lagune\liste-fournisseurs.txt -Value "Liste fictive des fournisseurs de Lagune Services"
```

This file is used on day 4: it will be deleted, then restored from the backup. It must exist **before** the first copy.

**Check**: `Get-Content C:\Lagune\liste-fournisseurs.txt` prints the sentence.

### 7. Auto-shutdown (Ops role)

Azure portal, `vm-lagune-01`, **Operations**, **Auto-shutdown**.

- Switch **On**.
- Time: `19:00`. Time zone: UTC by default (it is Abidjan time).
- Notification before shutdown: **Yes**, with the team address.
- **Save**.

**Check**: when you return to the page, the switch is **On** with the chosen time.

A machine stopped from the portal is "deallocated": you no longer pay for its compute, but its disk is still billed, and so is its backup in the vault. The night backup also works on a switched-off machine.

### 8. The backup (Ops and Security roles)

Azure portal, `vm-lagune-01`, **Backup**.

1. **Recovery Services vault**: **Create new**. Name: `rsv-<PREFIX>`. The portal creates it in the same resource group and region as the machine.
2. **Policy sub type**: **Standard**. Default policy: one backup a day, kept 30 days. You can choose the time of the copy (at night).
3. **Enable Backup**.
4. Follow the notification. When it is done, reopen **Backup** on the machine.
5. To avoid waiting for the night: **Backup now**, choose the retention, **OK**. Follow **View all jobs**.

**Check**:

- the machine's **Backup** page shows the policy attached;
- the mention "Warning (Initial backup pending)" may appear before the first copy;
- the "Backup" job is running or finished. It can take a while: do not hold up the end of the session, check again on day 4 in the morning.

Look at the vault protections (read only): vault `rsv-<PREFIX>`, **Properties**. **Soft delete**: on by default, 14 days. **Immutable vault**: **leave it at "Disabled"**. **Never** choose "Enabled and locked": that lock is irreversible, and everything must be deleted at the end of the course.

### 9. The cost sheet (Dev role)

Ask Claude Code:

```text
How much does the machine vm-lagune-01 cost per month, and how do I switch it off?
Give me the parameters to enter in the official Azure pricing calculator, without inventing prices.
```

Open the official calculator: https://azure.microsoft.com/pricing/calculator/. Enter: region, system, size, disk, hours per month (auto-shutdown included), backup, Bastion (chosen SKU).

Create `docs/fiche-cout-vm.md` in your `lagune-ops` folder (`Set-Location $HOME\lagune-ops`, then `code docs\fiche-cout-vm.md`, Ctrl+S to save) with:

```markdown

| Item | Parameter |
|---|---|
| Region | <TRAINING_REGION> |
| Machine | Windows Server, size <ALLOWED_SIZE> |
| Disk | <type and size> |
| Hours per month | <number> (auto-shutdown at 19:00) |

- Portal: Virtual machines, vm-lagune-01, Stop (the machine is deallocated).
```

## Pitfalls

- **Opening remote desktop (port 3389) to the whole Internet to go faster.** That door stays closed. We use Bastion.
- **A public IP address on the machine "just in case".** None.
- **A password in the repository or in a message.** It goes in the team vault.
- **Forgetting auto-shutdown.** A forgotten machine is a bill.
- **Believing the budget stops resources.** It only warns.
- **Locking the backup vault ("Enabled and locked").** Irreversible.
- **Leaving Bastion Basic on.** Billed by the hour from its deployment.
- **Bastion Developer, two machines at once.** It handles only one.
- **A file created after the first backup.** It will not be in the day-4 copy: run **Backup now** again after creating it.
